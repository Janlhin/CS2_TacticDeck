# 工程规范

本文件是本仓库的规则全文，也是唯一载体；`AGENTS.md` 只是指向本文件各节的目录。规则面向"人 + AI 共同改代码"的场景，因此每条都尽量落成可机器判定的形式。

## 校验链

**核心主张**：AI 提升产出速度的同时提升了"语法正确但语义错误"的缺陷密度，因此拦截职责必须落在工具链上，且同一类缺陷至少要有两条相互独立的拦截路径。

强制通道（Rust 为主栈，按等价映射）：

| 层 | 本仓库做法 | 强制级别 |
|---|---|---|
| 版本控制 | Git + Conventional Commits + commitlint | 强制 |
| 类型与静态检查 | Rust 编译期 + TypeScript `strict` | 强制 |
| 代码规范 | `cargo clippy -D warnings` + ESLint（`--max-warnings=0`） | 强制 |
| 样式层 | SCSS + Stylelint（Token 变量豁免） | 有 UI 时强制 |
| 单元与集成测试 | `cargo test`（覆盖率阈值在首个 crate 落地后设定） | 强制 |
| 端到端 | Playwright | 有 UI 时强制 |
| 运行期校验 | `serde` + 显式校验（边界处） | 强制 |
| 提交门禁 | Husky 薄壳 → `scripts/hooks/*.ps1` | 强制 |
| 流水线 | GitHub Actions（权威判定） | 强制 |
| 文档 | `markdownlint-cli2` + `remark-validate-links` + `markdown-link-check` | 强制 |

**唯一入口**：`bun run verify`。它失败就不得提交；禁止 `--no-verify`、注释测试、放宽容错规则。

## 文档先行

先有文档，再有代码；先改文档，再改代码。五个文件，职责不可合并：

| 文件 | 单一职责 | 必填字段 |
|---|---|---|
| `README.md` | 这是什么、解决什么问题、怎么运行、怎么算做完 | 一句话定位；业务问题；技术栈与版本；目录结构；安装与运行命令；验收标准；已知限制 |
| `AGENTS.md` | 执行者入口目录，≤150 行 | 强制命令入口；禁止清单；条款锚点；项目特有约定 |
| `DECISIONS.md` | 追加式决策日志 | 编号；日期；决策；背景；被采纳方案；被否决的替代方案与理由；影响范围；复审条件 |
| `TASKS.md` | 任务队列与待裁决台账 | 目标；创建时间；完成判据（命令 + 退出码）；状态；完成时间 |
| `MANIFEST.md` | 第三方来源登记 | 名称；来源 URL；版本；SHA256；用途；许可结论 |

开工判据三条同时成立才允许第一次业务提交：**文件齐**（五文档存在且通过结构校验）、**字段实**（`README.md` 字段非空，"明确不做"有实质内容）、**任务立**（首个任务已入队且判据可机器判定）。在此之前只允许做两件事：改文档、让校验链跑起来。

文档变更同样受约束：新增要说明依据，修改要说明原内容为何不成立（"更新措辞"不是理由），删除要说明理由与替代。历史属于版本控制与 `DECISIONS.md`，不在主文档里留"已废弃"段落。

## 原子化

三个层级，逐级收紧：

1. **提交级**：一个提交只做一件可独立解释、独立回滚、独立通过校验的事。文档改动与对应代码改动，要么同一提交，要么文档在前、代码紧邻其后。
2. **功能级**：一个功能不夹带格式重排、依赖升级、无关重构。
3. **文件级**：单次改动尽量落在同一职责域；跨域改动拆开提交。

禁止：把多轮改动积压成一个巨型提交（`git bisect` 会失效）；在功能提交里夹带主版本升级（必须独立 `chore(deps):` 提交）。

## 歧义协议

**需求存在多种合理解释时禁止猜测推进**，必须构造 2–4 个具体选项交用户裁决，并说明"不裁决我会怎么做"。

必须停下询问的情形：影响公共 API 或数据结构；涉及删除、迁移、权限；涉及外部付费资源或凭据；验收标准本身有歧义；与既有 `DECISIONS.md` 冲突。

不允许询问的情形（先自查）：仓库内已有明确约定；答案可由代码或文档直接读出；属于实现细节且可低成本回退。

提问格式：一次问完、批量交付，每个问题给选项与影响；不边做边问。答不出的一律登记到 `TASKS.md` 待裁决清单，不猜。

## 检索纪律

先搜寻，后自研。检索顺序不得跳级：**包注册表 → 代码托管平台（GitHub / GitLab / Gitee）→ 官方文档 → 社区讨论 → 自写**。

找到之后按三条路径处置：

- **路径 A：读源码学设计后自写**。须留下对照记录，且记录提交时间不晚于首个实现提交。
- **路径 B：引入现成依赖或工具**。须先做引入前评估（维护活跃度、许可证、体积与传递依赖、是否与既有依赖功能重复），并登记到 `MANIFEST.md`。
- **路径 C：逆向既有产物**。须先出许可结论；产物不入库。

**借鉴与复制的边界**：无明确许可证的项目一律只读、不抄、不引入。复制代码 = 复制其许可证义务与风险。

## 清理纪律

严格区分两种"冗余"：**校验冗余**要保留（同一缺陷两条独立拦截路径）；**代码冗余**要清除。触发分三层：

- **增量层**：每次提交发现即清，不留 TODO 文案。
- **定期层**：每迭代末做一次深度清理，产出独立 `chore:` 提交；文档过期内容并入同一时间点。
- **阈值层**：CI 门禁（重复代码率、未使用依赖、覆盖率）触发即修；**不得人为抬高阈值以"通过"**。

过期文档的信号：同一件事两处描述且措辞不同；描述的行为在代码中已不存在；章节标题带"旧""废弃""历史"字样。

## 目录与文件放置

根目录按白名单，子目录按判据。

根目录允许：五个文档；包管理与锁文件（`package.json` / `bun.lock` / `.bun-version`）；构建与静态检查配置（仅工具默认会读的位置，其余移入 `config/`）；版本与忽略规则（`.gitignore`、`.gitattributes`、`.editorconfig`、`.npmrc`）；协作与平台配置（`.github/`、`.husky/`）；法务与变更记录（`LICENSE`、`CHANGELOG.md`）。此外 `docs/`、`scripts/`、`crates/`、`apps/` 作为承载实现与规范的子目录。

**白名单之外新增根目录条目必须先询问并获批准，不得先放后报**；批准后补两件事：写入 `README.md` 的目录结构字段、在 `DECISIONS.md` 写明理由。

子目录三条判据：**同类就近**（该目录已有 3 个以上同类文件则跟随其规则）；**无同类则留痕**（位置选择记入 `DECISIONS.md`）；**目录内类型一致**（不混放组件与工具函数、源码与生成物、常量与副作用）。

## 脚本基线

- 所有脚本、CI 步骤、Git hooks 使用 **PowerShell 7.4+**；禁止新增 `.cmd` / `.bat`，禁止在项目自写代码中调用 `cmd.exe`、`powershell.exe`。
- **入口唯一**：业务逻辑只存在于 `.ps1`；`package.json` scripts、钩子、CI 只做 `pwsh -NoLogo -NoProfile -File …` 转发。
- 钩子必须是 `sh` 薄壳（LF 行尾，CRLF 会被 `sh` 读进命令），内容只有一行 `exec pwsh …`。
- 无法用 pwsh 完成时先提案，不得自行降级。

## 版本号

SemVer `X.Y.Z`：不兼容改动升主版本；兼容新功能升次版本；兼容修正升修订号。

硬性要求：先定义公共 API；禁止前导零；按数值比较而非字符串比较；已发行版本不改动；`0.y.z` 视为不稳定；`v1.2.3` 的 `v` 只是 tag 前缀，版本号本身是 `1.2.3`。tag 一旦推送不改，发错就发新版本。

提交类型与版本近似映射（仅用于自动化推算，最终以"是否兼容"为准）：`feat:` → 次版本；`fix:` → 修订号；`BREAKING CHANGE:` 或 `!` → 主版本。

## 交付说明

每次交付必须给四项，缺一不可：

1. **改了什么**：文件清单 + 一句话意图，逐条对应到原子提交。
2. **验证证据**：命令原文 + 退出码（不是"结果：通过"）。
3. **未验证项**：因环境、权限、凭据或网络限制没验证的部分，不得隐去。
4. **遗留项**：已知问题、待人工确认事项、建议的下一步。

末尾必须附一行当前未决议清单；一项都没有时写「当前无待裁决项」。这条是提示，不是停机等批准。

## 校验矩阵

| 缺陷类型 | 第一路径 | 第二路径 |
|---|---|---|
| 文档格式 / 结构 | 编辑器 lint | CI `markdownlint-cli2` |
| 内部锚点失效 | 编辑器引用提示 | CI `remark-validate-links` |
| 外部断链 | 编辑器链接提示 | CI `markdown-link-check` |
| 文档与代码不一致 | pre-commit 生成 + `git diff --exit-code` | CI 同一检查 |
| 命令不可执行 | 本地试跑 | CI 抽取 README 代码块实跑 |
| 条目字段缺失 | pre-commit 字段检查 | CI 同一检查 |
| 类型 / 契约不一致 | 编译器（Rust / TS strict） | Clippy / ESLint |
| 行为回归 | `cargo test` / 组件测试 | Playwright 端到端 |
| 脚本漂移 | `.cmd` / `.bat` 计数 = 0 | CI 同一条检查 |
| 许可污染 | `MANIFEST.md` 登记审查 | 依赖许可扫描 |

最后一行「删改未说明理由」「内容过期未删除」只有定期审查一条路径，无自动判据——因此定期清理节点必须写进排期，否则这两类缺陷完全没有拦截。

## 删除授权

分三级，**禁止先删后报**：

- **白名单（自主删）**：本仓库生成物、已声明废弃的文件、无引用的临时脚本；删除后在交付说明列出清单。
- **灰名单（先提案）**：被代码或文档引用的文件、`docs/` 下任一文档、`MANIFEST.md` 条目；须先说明替代位置。
- **黑名单（不删）**：`LICENSE`、`DECISIONS.md` 中已决条目、Git 历史、他人提交。
